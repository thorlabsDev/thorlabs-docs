---
title: "Vendor marketplace"
description: "Create and manage pass-holder rental checkout links when the dashboard Vendor flow is available."
---

The vendor marketplace lets an eligible pass holder offer time-limited, location-specific access to another user through a checkout link. It is a separate flow from [direct USDC rentals](/dashboard/rentals): vendor offers use the live SOL price, duration, revenue share, and availability shown by the dashboard.

<Warning>
  Use this workflow only when the current dashboard exposes the relevant **Rent
  out** and **Vendor** controls. Their absence means the marketplace is not
  available for that pass, location, account, or environment. Do not reuse an
  old checkout link or price table.
</Warning>

## Create an offer

<Steps>
  <Step title="Choose an owned pass">
    Open **Endpoints → Endpoints**, select the eligible pass you own, and review
    its current locations. Rental access cannot be listed as an owned pass.
  </Step>
  <Step title="Open Rent out">
    Choose **Rent out** for the intended location. If the control is disabled or
    absent, do not work around it.
  </Step>
  <Step title="Review the live offer">
    Select only a duration and SOL amount accepted by the current form. Confirm
    the pass, location, amount, expiry, and any displayed revenue split before
    creating the offer.
  </Step>
  <Step title="Share the generated checkout link">
    Send the new link to the intended renter. A checkout link can expire or be
    claimed, so never promise access until the dashboard marks the rental
    active.
  </Step>
</Steps>

## Manage offers and rentals

Open **Endpoints → Vendor** to review pending checkout links, active and expired rentals, and the revenue information currently available to your account. Use the dashboard controls to cancel a pending offer, inspect a rental, or create an extension offer when those actions are available.

An offer and an active rental are different states. Creating or sharing a link does not activate access; the renter must complete the current checkout and the backend must confirm it.

## Safety rules

- Never publish checkout links in a public issue, log, or documentation example.
- Treat all displayed prices, durations, revenue shares, deadlines, and extension options as live values.
- Do not request a renter's seed phrase, private key, endpoint token, or wallet secret.
- Confirm payment and activation in the dashboard; do not rely on a screenshot or a transaction signature alone.
- Contact [ThorNode support](mailto:support@thornode.io) before retrying an ambiguous payment or manually promising access.

For access created through the separate platform-operated catalog, see [Direct rentals](/dashboard/rentals).
