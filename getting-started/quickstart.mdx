ThorNode access starts in the dashboard. You sign in with Discord, connect an owned pass or an active rental, and then create credentials for the locations available to that access.

<Note>
  Open the dashboard from [thornode.io](https://www.thornode.io). If its
  dashboard link is unavailable, contact [ThorNode
  support](mailto:support@thornode.io) instead of guessing an address from an
  old bookmark.
</Note>

## Before you start

You need:

- A Discord account
- A ThorNode pass or an active rental
- A Solana wallet if you need to prove pass ownership, rent access, or renew a pass
- An HTTP client such as `curl` for the test request

<Steps>
  <Step title="Login with Discord">
    Open the dashboard from [thornode.io](https://www.thornode.io), choose **Login with Discord**, and authorize the requested account access.

    Your Discord identity is your dashboard account. Wallets and product access are associated with this account.

  </Step>

  <Step title="Register a Solana wallet">
    Open **Wallets**, connect the wallet that owns your pass or will pay for a rental, and approve the registration message.

    You can register up to three wallets. The signature proves that you control the address; never share your seed phrase or private key.

  </Step>

<Step title="Choose an access source">
  Use an eligible pass you own or an active rental. If **Rent** shows a current
  catalog, you can purchase time-limited access there. A visible product tab is
  not proof of eligibility; use the enabled controls, locations, and current
  backend response for the selected access.
</Step>

  <Step title="Create a token for one location">
    Open **Endpoints** and select your access, network, and location. Generate or copy the token shown for that location.

    Tokens are independent per location. A token for one location does not authenticate requests to another location.

  </Step>

  <Step title="Optionally restrict the token by IP">
    Add one public IPv4 address to allow RPC and WebSocket requests only from that address. Leave the field blank and save to remove the restriction.

    Skip this setting while testing from a connection whose public IP changes.

  </Step>

  <Step title="Copy an endpoint and test it">
    Copy the full SSL RPC URL from the dashboard. Do not reconstruct the URL or append the token yourself.

    ```bash
    export THORNODE_RPC_URL='<full SSL RPC URL copied from the dashboard>'

    curl --fail-with-body --request POST "$THORNODE_RPC_URL" \
      --header 'content-type: application/json' \
      --data '{"jsonrpc":"2.0","id":1,"method":"getLatestBlockhash"}'
    ```

    A JSON-RPC response confirms that the URL, token, and optional IP restriction are working together.

  </Step>
</Steps>

<Warning>
  Treat every endpoint token as a secret. Do not commit it to source control,
  include it in a client-side application, or paste it into support messages.
</Warning>
