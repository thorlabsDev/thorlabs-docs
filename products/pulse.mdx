**Planned, availability-unverified integration.** Pulse is the defined QUIC stream of transactions decoded from Solana shreds. Each payload is a decoded transaction, not a raw shred or a decoded shred object. A target visible in the dashboard does not prove that the replacement service, authentication, client, and schema are deployed in your environment.

## Use Pulse when

Use Pulse only after a ThorNode owner confirms the service is deployed for your environment and supplies the client, trust configuration, authentication contract, and schema.

Choose [Raw Shred Stream](/products/raw-shred-stream) when you need raw Solana shred bytes. Choose [Yellowstone gRPC](/products/yellowstone-grpc) when you need a Yellowstone Subscribe-compatible filtered stream.

## Connection contract

| Item                       | Value                                                             |
| -------------------------- | ----------------------------------------------------------------- |
| Transport                  | QUIC over UDP                                                     |
| Payload                    | Transactions decoded from Solana shreds                           |
| Target                     | Location target copied from the dashboard                         |
| Authentication             | Selected access and location token in a versioned control message |
| Server identity and trust  | Confirmed during onboarding                                       |
| Payload and control schema | Pinned during onboarding                                          |
| Supported client           | Supplied or confirmed during onboarding                           |
| Deployment availability    | Confirmed by a ThorNode owner for the exact environment           |

## Get the integration package

First obtain owner confirmation that Pulse is deployed for the intended environment. A dashboard target by itself is configuration evidence, not a deployment check. Then copy the target and token for one location and obtain all of the following from ThorNode onboarding or [support](mailto:support@thornode.io):

- Supported client package or build, including its version and installation steps
- Server name, trust roots, and the expected QUIC/TLS identity checks
- Versioned control-message schema and exact token field
- Confirmation that token enforcement is enabled on the selected deployment
- Pinned decoded-transaction payload schema and decoding contract
- Reconnect, gap, ordering, and current limit behavior for your access

ThorNode does not publish a generic wire example because the dashboard target and token do not define the client, trust, authentication, or payload contract.

## Prepare the stream

<Steps>
  <Step title="Confirm deployment readiness">
    Obtain owner confirmation that the selected environment runs the supported
    Pulse replacement, enforces authentication, and has a pinned client and
    payload contract.
  </Step>
  <Step title="Choose one location">
    Select an active access and enabled location, then copy the Pulse target and
    its token together.
  </Step>
  <Step title="Install the supported client">
    Pin the onboarding-confirmed client and payload schema for that deployment.
  </Step>
  <Step title="Verify the server">
    Apply the supplied trust configuration and require the expected server
    identity during the QUIC handshake.
  </Step>
  <Step title="Authenticate and decode">
    Send the token in the supplied control-message field, then decode incoming
    transactions with the pinned schema.
  </Step>
</Steps>

<Warning>
  Never place a Pulse token in a URL or query string, and never use a client
  that skips certificate, hostname, or server-identity verification. If the
  deployment delivers transactions without the required token, stop and report
  it to ThorNode.
</Warning>

The success signal is an identity-verified QUIC session that accepts the control-message credential and yields a transaction matching the pinned payload schema. A completed handshake by itself is not success.

## Run in production

- Permit outbound UDP/QUIC traffic to the dashboard target.
- Keep credentials out of source control, logs, and crash reports.
- Bound processing queues and monitor consumer lag.
- Reconnect with bounded exponential backoff and jitter.
- Detect gaps and reconcile application state when correctness requires it.
- Reuse connections instead of opening unbounded concurrent sessions.

## Troubleshooting

| Symptom                   | Verify                                                                      | Expected result                                                              | Action                                                   |
| ------------------------- | --------------------------------------------------------------------------- | ---------------------------------------------------------------------------- | -------------------------------------------------------- |
| Handshake fails           | Target, server name, trust roots, and outbound UDP policy                   | The client verifies the server and opens a QUIC session                      | Restore the supplied trust configuration or network rule |
| Authentication fails      | Token and target share a location; control schema and client version match  | The confirmed deployment accepts the versioned authenticated control message | Recopy the token and restore the pinned integration      |
| No transactions arrive    | Access is active; location exposes Pulse; decoder matches the pinned schema | The stream yields a transaction matching the pinned payload schema           | Confirm entitlement and schema with onboarding           |
| Works on one network only | Firewall, VPN, and egress policy permit QUIC                                | The same confirmed target opens from the intended runtime                    | Allow outbound UDP to the supplied target                |
| Consumer falls behind     | Queue depth and work in the receive path                                    | Queue depth remains bounded under expected load                              | Bound the queue and move expensive work downstream       |
