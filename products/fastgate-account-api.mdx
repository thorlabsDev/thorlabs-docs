FastGate is ThorNode's account-query route behind ThorEdge RPC. Send a standard routed method to the complete ThorEdge HTTPS URL; a successful query returns its result in a JSON-RPC response.

## Use FastGate when

Use FastGate for the 14 routed account methods listed below. You do not need a FastGate hostname or a second credential.

Choose [Yellowstone gRPC](/products/yellowstone-grpc) when your application needs a persistent filtered stream instead of point-in-time account queries.

## Connection contract

| Item                  | Value                                               |
| --------------------- | --------------------------------------------------- |
| Transport             | HTTPS, JSON-RPC 2.0                                 |
| Endpoint              | Complete ThorEdge RPC URL copied from the dashboard |
| Authentication        | Credential carried by the copied URL                |
| Credential scope      | Selected ThorEdge access, network, and location     |
| Separate FastGate key | None                                                |
| Live limits           | **Usage** and **Limits** in the dashboard           |

## Send an account query

You need a ThorEdge HTTPS URL, `curl`, and `jq`. Create or select a location token under **Endpoints → Endpoints**, then copy its complete HTTPS URL.

```bash
export THORNODE_RPC_URL='<copied-https-url>'
set -o pipefail

curl --fail-with-body "$THORNODE_RPC_URL" \
  --header 'content-type: application/json' \
  --data '{
    "jsonrpc": "2.0",
    "id": 1,
    "method": "getAccountInfo",
    "params": [
      "11111111111111111111111111111111",
      { "encoding": "base64" }
    ]
  }' \
  | jq '{
      jsonrpc,
      id,
      accountFound: (.result.value != null),
      error: (.error // null)
    }'
```

Expected output:

```json
{
  "jsonrpc": "2.0",
  "id": 1,
  "accountFound": true,
  "error": null
}
```

`accountFound: true` and `error: null` confirm that ThorEdge accepted the query and returned the System Program account.

## Routed methods

FastGate currently recognizes these 14 method names.

Standard Solana methods:

- `getAccountInfo`
- `getMultipleAccounts`
- `getBalance`
- `getTokenAccountBalance`
- `getTokenSupply`
- `getLargestAccounts`
- `getMinimumBalanceForRentExemption`
- `getTokenLargestAccounts`
- `getProgramAccounts`
- `getTokenAccountsByOwner`
- `getTokenAccountsByDelegate`

Use the [Solana JSON-RPC reference](https://solana.com/docs/rpc) as the request and result baseline for these methods. Validate every optional field, encoding, filter, and commitment behavior your application depends on against the current ThorNode response.

V2 methods:

- `getProgramAccountsV2`
- `getTokenAccountsByOwnerV2`
- `getTokenAccountsByDelegateV2`

## Guided integration: V2 methods

The three V2 names are routed, but their response envelope is not a public contract. Before you build against one, obtain these artifacts from [ThorNode support](mailto:support@thornode.io):

- Exact request parameters and allowed values
- Response envelope and field types
- Pagination cursor, termination, and consistency semantics
- Supported encodings and filters
- Error, retry, response-size, and limit behavior

Do not infer the V2 envelope from another provider or archived ThorNode documentation.

## Run in production

- Add selective filters to program-wide queries and request only the account data you need.
- Set explicit connect, request, and response-size limits.
- Treat non-2xx responses and JSON-RPC `error` objects as failures.
- Retry only transient failures with bounded backoff and jitter.
- Do not assume JSON-RPC batch support unless your access contract documents it.
- Keep the complete RPC URL in a server-side secret store and redact it from telemetry.

## Troubleshooting

| Symptom                       | Verify                                                          | Expected result                                          | Action                                                       |
| ----------------------------- | --------------------------------------------------------------- | -------------------------------------------------------- | ------------------------------------------------------------ |
| Unauthorized or forbidden     | ThorEdge access, location, token, and optional IPv4 restriction | One listed account method returns a JSON-RPC result      | Recopy the complete ThorEdge URL                             |
| Method not found              | Exact spelling and the routed list above                        | The request uses one exact supported method name         | Use a listed method or a different RPC route                 |
| Invalid params                | Matching Solana definition or supplied V2 contract              | The request fields and types match the selected method   | Correct the request; retries will not fix invalid input      |
| Response is too large or slow | Filters, requested data, and current limits                     | The filtered response completes within the client bounds | Narrow the query and set a response-size limit               |
| Rate limited                  | Current traffic against **Usage** and **Limits**                | Traffic remains below the applicable live limit          | Reduce concurrency and retry transient failures with backoff |
